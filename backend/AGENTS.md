# Правила разработки бэкенда

## Назначение

Каталог содержит Laravel API, аутентификацию, доменную модель, интеграцию с Яндекс.Картами, очереди и хранение данных.

## Архитектура

- Контроллеры отвечают только за HTTP-ввод, авторизацию, вызов прикладной операции и формирование ответа.
- Валидацию нетривиального ввода оформлять через Form Request.
- Внешний источник изолировать контрактом; конкретный клиент Яндекс.Карт не должен попадать в контроллеры.
- Долгий импорт выполнять через очередь. Job обязана быть идемпотентной, иметь timeout, backoff и обработку окончательного сбоя.
- API версионировать префиксом `/api/v1` и возвращать данные через API Resources.
- Доступ к организациям всегда ограничивать владельцем; чужой ресурс не должен раскрывать своё существование.

## Данные и безопасность

- Использовать `$fillable` или атрибут `Fillable` только для разрешённых полей.
- Инварианты закреплять ограничениями и индексами БД, а не только проверками приложения.
- Повторный импорт отзывов выполнять через уникальный внешний идентификатор и `upsert`.
- `env()` использовать только в файлах `config/`; в коде читать значения через `config()`.
- Для Sanctum не отключать CSRF. Разрешённые источники задавать через `CORS_ALLOWED_ORIGINS`.
- Не записывать в логи cookies, токены, прокси-учётные данные и полный HTML ответа источника.

## Стиль и проверки

- Соблюдать типизацию PHP 8.3+ и всегда указывать возвращаемые типы.
- Использовать фигурные скобки для всех управляющих конструкций.
- Новые Laravel-файлы создавать через `php artisan make:* --no-interaction`.
- После правок PHP выполнять:

```bash
vendor/bin/pint --dirty --format agent
php artisan test --compact
composer audit
```

- Сетевые обращения в тестах всегда подменять через `Http::fake()` и запрещать неожиданные запросы.
- Основные HTTP-сценарии проверять feature-тестами: успешный ответ, 401, 404, 422 и важные побочные эффекты.
